# Add N=16384 to both overhead tables — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a 16384-flow column to the LPCC buffer table (`overhead.md`) and the DCQCN maintenance table (`overhead-maint.md`), reusing the existing 64–4096 dumps and only simulating the new 16384 point.

**Architecture:** Two shell-driver edits add a `TABLE_COUNTS` knob (decouples "which N to render" from "which N to simulate") plus a per-N SIM rule for the maintenance driver (16384 → 0.6 s so 4 GB can drain the 100 G DCI link). Then run only 16384 for each table and rebuild over all five columns from existing + new dumps. No analyzer or C++ change.

**Tech Stack:** Bash drivers, the existing stdlib `analyze-overhead.py` + its pytest suite, ns-3.39 binary (already built).
